## 4. ข้อสรุป

- **Mac (GPU)**: ผ่านเป้า 3 วินาทีที่ 5 คนพร้อมกัน (median 1.6 s) ใช้หน่วยความจำ 46% ของ 16 GiB, CPU แทบไม่ใช้
- **CLIM000551VM01 แบบ CPU อย่างเดียว**: คำสั่งไทยคนเดียวใช้ ~3 s (ฝั่ง server 1.7 s) แต่ **ไทยพร้อมกัน 3 คนใช้ 9–10 s** เพราะ CPU เต็ม
  การเพิ่ม worker บน CPU ไม่ช่วยเมื่อ CPU เต็มแล้ว อังกฤษผ่านเป้า (≤ 2.1 s ทุกระดับ)
  เครื่องจริงมี 16 คอร์ (มากกว่าที่จำลอง 1.6 เท่า) คาดว่าไทย 3 คน ~6 s ซึ่งยังเกินเป้า → ต้องวัดซ้ำบนเครื่องจริงก่อนตัดสินใจ
- ถ้าจะใช้ CLIM: ตั้งไทย 1–2 worker (คนที่เกินใช้ fallback แทนรอ) หรือหาเครื่องที่มี GPU สำหรับ STT ไทย
- RAM ไม่ใช่ปัญหาบน CLIM (ใช้ 6.5 GiB จาก 47 GiB ที่ว่าง)

## วิธีวัดและข้อจำกัด

- CPU% = เวลา CPU สะสมต่อเวลาจริง หารจำนวนคอร์ (100% = ทุกคอร์เต็ม) · RAM = RSS สูงสุดของ process รวมตามชนิด · GPU memory = `torch.mps.driver_allocated_memory()` ต่อ worker
- GPU utilization ของ Mac มาจาก `ioreg` ซึ่งเป็นค่าของทั้ง GPU จึงแสดงเป็นส่วนที่เพิ่มจากตอนว่าง (ตอนว่าง 5% เฉลี่ย)
- Docker ใช้ `--cpuset-cpus` ให้ container เห็นจำนวนคอร์จริงเหมือน server (รอบก่อนที่ใช้ `--cpus` ช้ากว่าความจริงเพราะ PyTorch เปิด thread เกิน: `2026-11-13-voice-load-docker-4cpu-stt-services.md`)
- ขั้น 1, 7, 8 วัดใน Chrome headless 6 หน้าต่างบนเครื่องเดียวกัน ซึ่งแย่ง CPU/GPU กับ server (CLIM จำลองใช้ทุกคอร์ของ Mac) เวลารวมจึงสูงกว่าใช้งานจริงเล็กน้อย
- p95 มาจาก 3–15 ตัวอย่างต่อระดับ ใกล้เคียงค่าสูงสุด · เสียงทดสอบเป็นเสียงสังเคราะห์ macOS
- รอบแรกของ CLIM มีคำสั่งอังกฤษล้มเหลวชั่วคราว (ทำซ้ำในลำดับเดียวกันแล้วไม่เกิด) ตัวเลขข้างบนมาจากรอบที่วัดใหม่ทั้งหมด
